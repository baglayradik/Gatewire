# Gatewire Demo

Пример приложения на SwiftUI, которое работает с публичным тестовым API [DummyJSON](https://dummyjson.com).

## Что показывает пример

| Экран | Возможность Gatewire |
|---|---|
| **Каталог** | Публичная зона (`.none`): товары загружаются без входа, постранично. |
| **Аккаунт → Вход** | Запрос без авторизации и сохранение токенов через `client.auth.signIn(with:)`. |
| **Аккаунт → Профиль** | Авторизованная зона (`.required`): токен подставляется автоматически. |
| **Аккаунт → События** | Поток `AuthEvent`: вход, автоматическое обновление токена, выход. |

Токен живёт одну минуту. Через минуту после входа нажмите «Обновить профиль»: токен
обновится сам, а в журнале появится событие «Токен истёк и обновлён автоматически».
После перезапуска приложения сессия восстанавливается из Keychain.

Формат ответов DummyJSON отличается от RFC 6749, поэтому в примере используется своя пара
`RefreshableCredential` и `CredentialRefresher` со стратегией `.refreshable` —
см. [SessionCredential.swift](GatewireDemo/Networking/SessionCredential.swift).

## Структура

```
GatewireDemo/
├── Networking/
│   ├── Routers.swift            роутеры AuthRouter и ProductRouter, модели ответов
│   ├── SessionCredential.swift  учётные данные и обновление токена
│   └── DemoAPI.swift            настройка APIClient и методы API
├── Session/SessionModel.swift   состояние сессии, события авторизации, тексты ошибок
└── Views/                       экраны каталога и аккаунта
```

## Запуск

1. Откройте `GatewireDemo.xcodeproj` в Xcode 16 или новее.
2. Выберите симулятор iOS 17+ и запустите схему `GatewireDemo`.
3. Во вкладке «Аккаунт» уже подставлены открытые демо-учётные данные DummyJSON (`emilys` / `emilyspass`).

Пакет подключён по локальному пути `../..`. В своём проекте подключайте его по адресу
`https://github.com/baglayradik/Gatewire.git`, как описано в [README](../../README.md).
